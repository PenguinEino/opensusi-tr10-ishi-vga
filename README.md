# ISHIロゴ VGA案の検討 — 2026-09-24

**実装時の入口：[APRtools採用版と参照規約](docs/APRTOOLS_ADOPTION.md)。** 使用する版・セル・フレームは[toolchain.lock.json](toolchain.lock.json)で固定し、実コードのパス解決結果を[apr_resolution.json](docs/apr_resolution.json)に保存した。以下は初期の方式検討であり、旧版セルの面積例等を現在の実装設定として使用しない。

過去の検討ではリング出力を専用ピンへ出し、ジャンパでCLKへ戻す構成だったが、最新指示によりリング不搭載へ変更した。[現在の仕様](docs/PIN_PLAN.md)。[TR-1um論理回路フローの調査](research/TR1UM_DIGITAL_FLOW.md)は履歴として維持する。

**画質の下限は64×54程度。第一候補は、37個の矩形で近似した128×108のロゴを4倍表示し、640×480・60 Hz相当のVGA信号を外部6.3 MHzクロックで生成する方式。RGBは各2 bitとする。**

これは方式検討と画像サンプルであり、合成・配置配線・タイミング・実機動作の完了報告ではない。

## 会話から把握した条件

- 10ピン・1800×1000 µmの枠は平衡3進回路で埋まっている。今回のVGAは追加の1枠、14ピン・1800×1800 µmを想定する。
- CPU案はスタセル面積と残り時間から取りやめ。単機能のロゴ表示へ変更するのは妥当。
- 最新の締切発言は「明日いっぱい」。この発言が9/24なら提出期限は9/25（金）中。先の「土曜くらい」ではなく、最新発言を優先する。真のテープアウトは9/28という会話上の情報。
- テンプレートのフレームへ自分で載せる必要がある。画像が出るRTLだけでなく、GDS・回路ネットリスト・統合後の確認までを締切に含める。
- 「devブランチのフレームにある21件のエラーは無視してよい」は主催者が指した既知のエラーについての話で、新規回路のDRCエラー全般を許容する意味ではない。
- 当初の「5チップ」はあるが、追加枠の配布個数が別に確定したとは読み取れない。今回の方式は1チップで動く構成にする。

2. [色数比較](samples/color_comparison.png)：64×54で、主要6色・RGB222・RGB111・単色を比較。
3. [矩形描画比較](samples/geometry_comparison.png)：元画像を37矩形で近似し、座標を各解像度へ丸めたもの。縮小画像に生じる中間色の縁を除去できる。元PNGとのピクセル完全一致ではない。
4. 実際の640×480の有効画面に配置した候補：[128×108を4倍](samples/vga_geometry_128x108.png)、[64×54を8倍](samples/vga_geometry_64x54.png)。両方とも512×432を中央配置する。黒い帰線期間は画像には含めない。

| ロゴの解像度 | 3 bitインデックスの生データ量 | 目視評価 |
|---|---:|---|
| 32×27 | 2,592 bit / 324 B | ISHIとは読めるが、細線・隙間が潰れる。緊急の縮小候補 |
| 48×41 | 5,904 bit / 738 B | 読めるが、線幅・文字の比率が不揃い。積極採用する利点は小さい |
| 64×54 | 10,368 bit / 1,296 B | **十分な最低線**。細線は1～2画素。8倍表示しやすい |

このビット数は画像表現の比較用であり、実装面積ではない。定数ROMは論理最適化できる一方、SRAMマクロなしで一般のフレームバッファを作ると非常に大きくなる。

## 描画方式

| 方式 | 今回の評価 |
|---|---|
| 640×480のフレームバッファ | 3 bitでも921,600 bit。固定ロゴには不要 |
| 低解像度の定数ROM | 自動変換が容易。最終的には組合せ論理となり得る。合成結果で比較する価値はある |
| 行パターン共有・ランレングス | ROMの改善案。復号制御や可変長処理を増やすより、座標区間の共有が扱いやすい |
| **矩形による手続き描画** | **固定ロゴに最適な候補**。文字も配線も軸に平行な矩形で表現できる |
| 外付けROM・MCUから画素ストリーム | チップ面積は節約できるが、外部回路と通信同期が主役になる。今回は予備案 |

単純に縮小PNGから同色の横ランを縦方向にまとめるだけでは、64×54でも180矩形、128×108では198矩形になった。アンチエイリアスの中間色が形を分断するため。これに対して、色の重なりを残して幾何形状へ描き直すと**両解像度とも37矩形**になる。

37矩形版は64・128のいずれもX境界34種類、Y境界24種類。境界比較を共有し、同色の矩形をORし、5色グループ間で優先順位を付ける構成が候補。37段の逐次優先MUXをそのまま残す実装は避ける。ROMと比較する際は、どちらも同じ電源・セルライブラリ・制約で合成する。

**矩形方式では、解像度を半分にしても面積が1/4になるわけではない。** 比較器のビット幅や座標定数は変わるが、形状数は同じ。これが128×108を先に試す理由。

## VGAタイミングと低速化

標準的な640×480系の総画素数は800×525、負極性HSYNC/VSYNC。25.2 MHz相当なら水平31.5 kHz・垂直60 Hzとなる。25.175 MHzの59.94 Hz系に対して約+0.10%で、Project Fも25.2 MHzを推奨している。[出典](https://projectf.io/posts/video-timings-vga-720p-1080p/)

水平の有効640・フロント16・同期96・バック48は、すべて16で割り切れる。そのため画素値を複数画素にわたって保持するなら、チップ自体が25 MHzで動く必要はない。

| ロゴ案 | 1クロックが表す横画素 | 外部クロック | 水平：有効 / FP / Sync / BP / 合計 | 水平カウンタ |
|---|---:|---:|---|---:|
| 128×108、4倍 | 4 | **6.3 MHz** | 160 / 4 / 24 / 12 / 200 | 8 bit |
| 64×54、8倍 | 8 | **3.15 MHz** | 80 / 2 / 12 / 6 / 100 | 7 bit |
| 32×27、16倍 | 16 | 1.575 MHz | 40 / 1 / 6 / 3 / 50 | 6 bit |

いずれも垂直は480 / 10 / 2 / 33 / 合計525ライン、10 bitカウンタ。同じ水平・垂直周期となる。640×480の表示互換性を保ちつつ、色の横方向変化を粗くする方式であり、モニタへ「128×108モード」を要求するものではない。

128案の例：水平カウンタh=0..199、垂直v=0..524。h<160かつv<480が有効。HSYNCは164≦h<188でLow、VSYNCは490≦v<492でLow。ロゴは16≦h<144、24≦v<456に置く。ロゴ座標はx=h−16、y=(v−24)>>2。境界比較にオフセットを織り込めば、引き算器は省ける。

RGBと同期をレジスタ出力にするなら同じ遅延でそろえる。帰線期間は白背景ではなくRGB=0。垂直カウンタは別の派生クロックで回すより、外部クロック＋行末enableで回す。外部リセットを用意し、解放時の同期化を設計に含める。

リング発振器単独は電圧・温度・個体差で走査周波数が動くため、第一候補は外部の安定したクロック源。6.3 MHz入力なら内部周期は約158.7 nsだが、**TR-1umでその周期が通ることは未検証**。比較・エンコード・配線遅延を含めて確認する。

## 色とピン

モノクロは色が重なる文字と背景の配線が一体化し、今回のロゴと相性が悪い。RGB111は成立するが、配線の色の違いが減る。RGB222では明るい青・水色・濃い青・薄紫を区別でき、14ピン枠なら優先したい。

RGB222は原画像のRGB値を厳密には再現できない。単純な最近傍量子化では明るい青と水色が同じコードになり得るため、サンプルでは識別を保つように6色のパレットを手で選択している。ディザは回路とエッジを増やすので採用しない。

| 機能 | 本数 |
|---|---:|
| R[1:0], G[1:0], B[1:0] | 6 |
| HSYNC, VSYNC | 2 |
| 外部CLK、RESET | 2 |
| VDD、VSS | 2 |
| 合計 | **10信号＋2電源** |

14ピンという数に電源が含まれるかが未確定でも、この最小構成なら両方の数え方に収まる。余裕があれば、カラーバー切替入力と内部状態観測出力を付ける。最終パッド番号・電源配線・保護回路はフレームに合わせて決める。

VGAのRGBは約0～0.7 V、75 Ω終端。白では1チャンネル約9.3 mAを負荷へ供給する必要がある。チップの小さいスタセル出力へこの負荷を直接負わせず、**チップはデジタル信号を出し、基板側のバッファ＋抵抗DACで駆動する**案がよい。DACはモニタの終端、バッファ出力抵抗、電源を含めて設計する。[Digilentの実装例](https://digilent.com/blog/new-product-announcement-pmod-vga/)

会話中の10 Vは平衡3進回路の電源検討であり、VGA用デジタル回路の電源を10 Vに決める根拠ではない。使用するスタセル・パッド・入力しきい値・外部バッファの対応電圧をそろえる。同期信号にも必要なレベル変換を設ける。

## 面積の見通しと未確定事項

使用可能面積は会話の値では3.24 mm²。ただし、フレームの1800×1800に対してコアへ使える内側の境界、電源幹線、入出力回路の占有を確認する必要がある。

公開APRtoolsのv64_8面積ライブラリには、NAND2=1049 µm²、DFFRB=4199 µm²とある。例えば128案の18 bitカウンタ＋8 bit出力レジスタなら、単純な26 DFF分は約0.109 mm²。ただしリセット同期、増分器、境界比較、描画、クロック・出力バッファ等は別。この数字だけで収まるとは言えない。[面積ライブラリ](https://github.com/jun1okamura/TR-1um_APRtools/blob/main/stdcell/v64_8/TR1um_5_stdcell_area.lib)

このライブラリのタイミングは明記どおり**PLACEHOLDER / NOT for STA**。面積の目安には使えるが動作周波数の保証には使えない。また、今回使うスタセルと同一版であることは未確認。

初回の合成セル面積は、仮にコア全面3.24 mm²が使えるなら、その50%程度=1.62 mm²以下を目標にすると配線余地を確保しやすい。これは合否規則ではなく暫定設計目標。実際のコアが小さければ目標も引き下げる。

## 締切までの優先順位

1. **128×108・矩形37個・RGB222・外部6.3 MHz**を基準とする。最初は静止画のみ。
2. カウンタ＋同期＋単色画面を先に成立させ、続いて矩形描画を足す。同じ条件でROM版の合成面積を比較できれば比較する。
3. フレーム全体のシミュレーションで周期、同期幅、表示位置、帰線中の黒、リセット復帰を確認し、RTLの出力画像を今回の参照画像と照合する。
4. セル合成・配置配線後の面積と遅延を見る。厳しければ64×54・3.15 MHzへ変更。それでも面積が厳しければ背景配線の本数や色の層を減らす方が効きやすい。
5. フレームへ配置し、DRC/LVS・電源・ピン対応を確認する。公式テンプレートはGDSと対応する回路ネットリストを要求する。[提出テンプレート](https://github.com/OpenSUSI/TR-1um_MPW_template)
6. 動画・スクロール・追加テキストは静止画と提出物が成立してから判断する。

## ファイルと再現

`python3 scripts/compare_logo.py` でPNG比較、実表示サンプル、矩形座標JSON、metrics.jsonを再生成できる（Python 3、Pillow、numpy、DejaVu Sansを使用）。量子化版の矩形JSONは非重複矩形、geometry版は**配列順の上書き**が必要な重なり付き矩形。座標は[x0,x1)、[y0,y1)の半開区間で、各行は[color,x0,y0,x1,y1]。

検証済みなのは、画像変換の再実行、量子化版の矩形からのピクセル完全再構築、比較画像の目視確認、およびタイミング数値の計算。RTL・GDSは今回まだ作成していない。
