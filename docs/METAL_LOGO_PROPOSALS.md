# Bに意味のあるメタル線を足す案

**後続の採用・完成版は「格子＋5線：電源枝」。** [最終コアは1792.8×897.2 µm、描画DRC 0、strict LVS合格](POWER_GRID_IMPLEMENTATION.md)。以下は採用前の比較記録であり、984.7 µmや短絡17対は当時の値。

2026-09-25。ユーザー指定の[土谷さんの記事](https://note.com/akira_tsuchiya/n/n0c720b3498b4)と、そのSiliwiz JSONを参照した候補。**見た目の第一候補はB＋4線分、意味を多く残すならB＋8線分。半枠に近い候補は、別字形の格子＋1線分で1783.8×941.5 µm。900 µm内に入ったとはまだ言えない。**

[比較ページ](../samples/metal_proposals/index.html)はネットごとのチェックボックスで線を切り替えられる。既知の組み合わせだけ合成・配線の数値を表示し、未知の組み合わせは「未測定」とする。[元Bの比較PNG](../samples/metal_proposals/b_comparison.png)／[格子版の比較PNG](../samples/metal_proposals/grid_comparison.png)。画像は設計参照であり、ゲートシミュレーションの画面ダンプではない。

## 記事から拾った意味

元ロゴは左のIがINV、SとHの左側がNAND、Hの右側と右のIがNORを表す。2入力A/Bを共有し、出力はY1=¬B、Y2=¬(A∧B)、Y3=¬(A∨B)。下側のmetal2横線は原作でも非接続の装飾。したがって、今回の追加は出力ドレイン同士を結ぶ線、またはソースと電源レールを結ぶ枝を選ぶ。[記事の回路図・端子配置](https://note.com/akira_tsuchiya/n/n0c720b3498b4)。

参照用画像の取得元は `research/logo_article/sources.json`。Siliwizの元データは `assets/ishi_logo_siliwiz_source.json`、Bの図形は `assets/logo_rectangles.json`。**今回の表示はコンタクトや隠れたポリ配線まで再現した抽出済みCMOSレイアウトではなく、端子の関係を残した部分的な図案**。全体としてINV/NAND/NORが電気的に成立するという検証は行っていない。

## 元Bの字形を変えない4案

全て128×108の元Bに線を追加。文字・拡散帯・既存の横線の座標は動かさない。RGB111・黒背景・RESETなし。追加数は**直線の矩形数**で、電気的なネットの本数とは区別する。既存Bの21矩形には含めず数えた。

|案|追加するもの|追加線分 / 合計矩形|セル数|セル面積 µm²|見た目と位置づけ|
|---|---|---:|---:|---:|---|
|元B|なし|0 / 21|256|356,363|比較基準。既測定1783.8×1119.7 µm|
|**B＋1**|Y1|1 / 22|287|395,497|左Iに縦線1本。最小変更だが左へ偏る|
|**B＋4**|Y1、Y3|4 / 25|302|407,365|左の縦線と右上の折り返し。中央のS/Hが読みやすく、控えめ|
|**B＋8**|Y1、Y2、Y3|8 / 29|329|445,213|中央のU字も復元。3つの出力という意味が最もよく残る|
|**B＋5**|VDDへ2本、VSSへ3本|5 / 26|305|418,270|上下へ枝が伸び、電源レールらしさが出る|

4案の新規P&Rはまだ実行していない。元B自体が約1120 µm高で目標を超えており、新案を「900に収まる」とは推定しない。セル数が近いからGDSも同じサイズ、という推定もしていない。

Y3はAの装飾的な末端を短縮した3矩形。VDDの中央2本は同じ拡散領域へ入っているため、今回は1本へまとめた。左VSSも同じソース領域へ直接下ろしてL字の横線を省いた。この省略は元JSONと接触先を見て選んだ図案上の判断であり、電流容量・寄生抵抗を評価した最適化ではない。

## 半枠を狙う別字形

こちらは前回の規則的な格子版へ追加した候補。**元Bの字形を保つ案ではない**。同じ「ISHI＋上下の帯」という構成を用い、共通字形と座標を使って論理を小さくする。通常3案には、NANDの出力領域とNORのソース領域を分けるため、下の拡散帯にも8 pxの切れ目を入れた。

|案|追加線分|セル数|セル面積 µm²|配線後最小寸法 µm|
|---|---:|---:|---:|---:|
|元の格子版|0|176|267,192|既測定1783.8×758.6|
|**格子＋1：Y1**|1|194|287,400|**1783.8×941.5**|
|格子＋4：Y1、Y3|4|225|319,797|未測定|
|**格子＋5：電源枝**|5|209|301,193|**1783.8×984.7**|
|格子＋1：線端を帯へ、幅16 px|1|201|295,740|未測定|
|格子＋5：線端・電源列を共通化|5|216|306,325|未測定|
|格子＋1：拡散帯の分割を省略|1|207|298,948|未測定|

最後の3案は端点や線幅のパラメーター比較。いずれも今回はセル面積が増えたため、優先候補にはしない。最下段は元格子版へINVの線だけを加えたものだが、単純な要素削除でも合成の結果が増える例となった。**追加線分数から面積を線形に計算しない。**

格子＋1は目標まで高さ41.5 µm（目標比4.6%超過）、格子＋5は84.7 µm（9.4%超過）。端子の外周への引き出しやフレーム接続の余白を含まず、今後小さくできる保証もない。現時点の「半枠に近い」案として扱う。

## パラメーターと描画上の注意

- **どのネットを残すか**：Y1 / Y2 / Y3 / VDD / VSS。意味を失った途中の線を断片的に戻すのではなく、接続を単位に追加した。
- **線分の予算**：1、4、5、8。折れ曲がった1本のネットは複数矩形になる。
- **元Bの字形を維持するか**：維持する案と格子版を混同しない。格子版の小面積を元Bへ流用しない。
- **線幅と端点**：通常の元Bは12 px相当、格子版の細線は8 px。比較版のY1は16 px。帯の中央で止めるか、既存の帯の端へそろえるかを比較した。
- **配色**：黒背景、赤い文字、水色のメタル、青・紫の拡散帯。RGB111ではmetal1/metal2の色を共通化している。画面上で同色の線が交差しても、原作の別層交差を同一ネットへ接続したという意味ではない。
- **装飾の下側metal2**：元B維持案では残す。削除した方が常に小さいとは限らないため、今回の測定と混ぜない。

## 実装・検証の範囲

10案全てに独立したRTL、参照画像、`config.py`、使用ファイルのSHA256を保存した。全案でRTLおよび最終BUFTH挿入後のゲートモデルが、同期獲得後2フレームの全tick照合に合格。元B系は各210,000 tick、格子系は各105,000 tick。試験側だけでFFを0へ初期化しており、任意起動状態の形式検証ではない。

元B系はCLK 6.30 MHz、格子系は3.15 MHz。両方とも640×480・60 Hz相当。VDD、CLK、HSYNC、VSYNC、R、G、Bで共通VSSを除く7端子。リングなし。外部パレットデコーダなし。

配線比較は固定APRtools/v59_4のまま実行。格子＋1と格子＋5を4行に置き、行割当を8再開×2,000,000試行で探索した。

|配線比較|格子＋1の高さ µm|格子＋5の高さ µm|
|---|---:|---:|
|通常配置、PRL閾値20|1265.5|1200.7|
|行割当探索後、PRL閾値20|946.9|984.7|
|格子＋1のみ、PRL閾値10|973.9|—|
|格子＋1のみ、PRL閾値40|946.9|—|
|格子＋1のみ、PRL閾値20＋span lane共有|941.5|—|

PRLとlane共有は固定上流が提供する配線設定で、各候補の`config.py`に保存。DRC規則や配線間隔、セル、層の定義を変更していない。上流変更はロックに記録されたPCell検索パッチだけ。

**新案の公式描画DRC・MDP・LVS・配線後STA・最終端子引き出し・フレーム統合は未実施。** 最小寸法のGDSも診断物である。実セル端子の接続検査結果は [metal_logo_results.json](metal_logo_results.json) の各 `physical` に記録する。

実GDS配置とv59_4 LEFの信号端子を独立に照合した結果、最小の格子＋1は649端子・欠落0・断線0・**短絡4ネット対**。格子＋5は696端子・欠落0・断線0・**短絡17ネット対**。両方とも未修復であり、寸法だけで実装済みとは扱わない。
