# A案の再挑戦

2026-09-25のユーザー指示。実装・検証は主エージェント1人で進める。

**後続の行割当改善で、同じ382セルのAが1783.8×1744.7 µmへ縮んだ。** 1800 µm角に入ったが、短絡75ネット対・断線0の診断段階。上流短絡修復は断線2件を生じたため不採用。[最新の配置・検証結果](A_ROW_PLACEMENT.md)。`build/ishi_vga_a_diagnostic.gds` はこの新しい未修復候補を指す。

以下は最初の探索の記録。最新指示「統合はまだやらないでいい。とりあえずAやって」に従い、フレーム統合を停止してA案を試した。この時点では31構成の合成、6構成の配置配線で1800×1800 µmには未達、最小の診断GDSは1783.8×2943.5 µmだった。B案の外周への10信号引き出しは完了済みで、既存の2つのスナップショット（14件・24件）の全ハッシュが一致することを再確認した。

`scripts/a_logo_trial.py` から始まる設計側の生成器で `experiments/a_*` に独立した設計を作った。初期カウンタは検証済み `descending_h79_v500` と同一。その後、横・縦の開始値、比較式・ビットマスク式、X/Y区間共有、RGBの区間共有、完全に同じ行の共用、色の重なりを使った式、Espressoによる論理式を比較した。B案固有の簡略RGB式は流用せず、A案の重なりを検証した。各案の参照画像は訂正済み37矩形を通常の画面座標で順に塗った独立ラスタから生成する。

最新の追加指示により**リング発振器は不搭載、外部CLKのみ**。信号10本＋電源2本でA/B共通。[現在のピン仕様](PIN_PLAN.md)。今回の面積にはリングをもともと含めていない。

## 検証の範囲

**機能:** 合成が完了した30構成で、上流のRTLとmerged-netlistの試験が6.30 MHz・各315,017tick一致。最初の389セル案と最小面積382セル案は、さらに最終BUFTH挿入後ネットリストを6.30/6.45 MHzの双方で照合し、RTLと合わせ各4条件・計1,260,068tickで一致した。全画素、HS/VS、フレーム折り返し、停止クロック中の非同期リセット、2段の解除同期を含む。セルモデルは単位遅延であり実機試験ではない。

**配線前STA:** 最小382セル案、typ 5 V/25℃、155 ns周期でreg→reg slack +110.086 ns。従来のコア比較設定を維持しており、出力負荷は固定LibertyのGIO OUT容量を上流が取得する設定。未承認のGIOフレームを実装した意味でも、通常ANAパッド・基板負荷を駆動できると確認した意味でもない。寄生・クロックスキュー・PVT全条件は未検証。

**最小診断GDSの接続:** GDS内の521配置インスタンスと実LEFの1,301信号端子を照合。端子取りこぼし0、信号断線0だが、**5つの混線成分が残る**。成分内で異なるネット同士を数えると16,847対あり、5か所だけ直せば済むという意味ではない。[接続監査](../experiments/a_phys_h63_alt6/build/audit/metal_connectivity.md)。ルータの端点表だけを根拠に合格扱いしない。

**公式描画DRC:** 固定PDKで `GC.ANT` 3件。合格ではない。LVS・MDPはこの不適合な診断GDSでは未実施。定数入力の電源接続、短絡修復、コア端子の引き出し、フレーム・電源パッド接続も未完了。B案のDRC/LVS合格結果をA案へ流用しない。

`a_h63_v512_x` は合成途中でABCが内部にBUFTHを選び、上流 `insert_bufth.py` の既存BUFTH検査で停止した。30完成構成とは分けて、失敗ログを保存した。上流コードの書き換えや別ライブラリへの切替は行っていない。

## 再現と版

APRtools `8f6962bf2df1618d633f8a81c230fec895fc83aa`、TR-1um `f408d3b5c23a8ebe44f02b0482a9270601e2880f`、v59_4 GDS/LEF/SPICE/typ Libertyは変更なし。上流への変更は既存のロック済みPCell検索パッチのみ。幾何・配置・配線設定は各試験のconfigに保存。`source_manifest.json` と `a_trials/results.json` に実際に使ったRTL・コード・設定・GDSのSHA256を記録した。

既に生成済み・ビルド済みの実験を生成器で上書きしない。再配置には別の試験名を使う。

```sh
python3 scripts/check_toolchain.py
.venv/bin/python scripts/run_apr.py --design-root experiments/a_h63_v500_x syn/syn.sh
.venv/bin/python scripts/a_logo_trial.py verify a_h63_v500_x
.venv/bin/python scripts/a_physical_trial.py a_h63_v500_x a_repeat_alt6 --rows 6 --seed 7 --pad-weight 0 --prl 20
# a_repeat_alt6 はまだ存在しない新しい出力先を指定すること
klayout build/ishi_vga_a_diagnostic.gds
xdg-open experiments/a_h63_v500_x/build/gates_6.45.png
```

上記の合成再実行はその試験のout/buildを更新するため、監査用の原本を残す場合は先に別の設計ディレクトリへ保存する。B確定ディレクトリやrootの過去実装は使わない。

## 元データと左下の訂正

ユーザー提供の[元JSON](https://note.com/api/v2/attachments/download/b564cf67e09246ac8dd0c072c88b3366)はSiliwiz version 1の図形データ。原文を `assets/ishi_logo_siliwiz_source.json`、取得元とSHA256を同名 `.provenance.json` に保存した。

JSONの左下metal1横線は `(x=82,y=226,width=63,height=9)`。以前のA案ではこの横線を左側の別の縦線までつなげてしまっていた。128×108の既存A案に対応させる訂正は、色1の矩形 `[1,11,62,46,65]` → `[1,25,62,46,65]`。矩形から余分な14×3画素分を除く（既存の縦線・赤文字との重なりを除いた最終画像の差分は18画素）。他の矩形やパレットを変更せず、37矩形のまま `assets/logo_rectangles_a_corrected.json` に保存した。元の37矩形ファイルも履歴として維持する。

今回、訂正済み37矩形の独立ラスタとRTL／最終ネットリストの出力が一致することを検証した。これは元JSONの全レイヤ・ビアを含む厳密なラスタ変換を証明したものではなく、既存A案の指定箇所を訂正した37矩形ロゴの一致検証である。
