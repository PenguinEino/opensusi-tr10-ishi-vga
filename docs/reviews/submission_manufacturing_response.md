## 修正版の検証

- 公式描画DRC 0、strict LVS PASS（23回路、トップ238ネット／325子回路、8端子一致）。
- MDPは元と同じCLK入力のFloating SG 1件。
- 実GDS端子704個の独立監査：欠落・断線・短絡0。VDD/VSS各1成分。
- RTLと修正ゲート回路の2フレーム各105,000 tick一致。
- 全131,072二値カウンタ状態の次状態と5出力をRTL／ゲートで照合。正常走査の52,500状態は既存画像参照とも一致。
- 1790素子のno-combine抽出SPICE：5 V/27℃、3.15 MHz、CLK両エッジ2 ns、出力1 pF、最大刻み1 ns。
- 通常の境界4試験540クロック＋電源投入後の128クロック、計668クロック一致。独立LVS参照回路110クロックも一致。
- 旧コアからECOを新規ディレクトリで再実行し、新GDSのSHA256一致、DRC／LVS／STA再合格。

電源投入試験の照合開始時はh=25、v=383で、観測時間内には正常の525行周期へ入らなかった。旧チェッカは正常走査範囲のみを照合するため0件で停止した。新チェッカは全二値状態でRTLとゲートの一致を確認して生成した参照表も使用し、範囲外での状態遷移・出力を128クロック照合する。期待画像を変更したり、照合なしをPASSにしたりしていない。**この電源投入過渡解析では画面同期の獲得を確認していない。** 全二値状態が最大49,928クロックで単一周期へ入る遷移モデルは別の証拠であり、アナログ保証ではない。

## STA失敗検出

`scripts/run_apr.py` から **直接** `syn/sta/sta.sh` を呼ぶ場合に、`sta_guard.py` と `sta_guard.tcl` を適用する。必要な時計・22個のCK/D端子・setup/hold/outputパス・開始終了マーカーを要求し、制約違反とエラーを拒否する。上流の `syn/syn.sh` 内部で実行されるSTAまでは置き換えないため、提出判定では必ず直接のguard付きSTAを実行する。

`scripts/test_sta_guard.py` で修正版はexit 0、元の容量違反・意図したTclエラー・途中exitの3条件はすべてexit 1と確認した。結果は提出フォルダの `review/sta_guard_controls/`。

物理ECO再現は `scripts/replay_clock_core.py --out build/新しいディレクトリ`。詳細・固定依存は提出フォルダの `REPRODUCE.md`。主担当が修正と検証を行い、独立レビュワーの再承認はまだ受けていない。
